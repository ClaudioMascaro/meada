# Meada 1.2.0

**Português (Brasil)** · [English](1.2.0.en.md) · [Español](1.2.0.es.md)

A 1.2.0 é uma versão minor dentro da [promessa de estabilidade para 1.x](../site/pt/stability.md):
só acrescenta, e nenhum item congelado quebra. A árvore declara **1.2.0** (workspace, pin do
`meada-core`, Dockerfile, defaults do compose e chart Helm), e a tag `v1.2.0` sai do main depois
do merge do PR destas notas. A publicação dos crates, do pacote npm preparado e do rascunho da
release do GitHub é do mantenedor. As mudanças detalhadas estão no [CHANGELOG](../../CHANGELOG.md).

## Mudanças

- **Leitura de pacotes** ([#532](https://github.com/ClaudioMascaro/meada/issues/532), [#533](https://github.com/ClaudioMascaro/meada/issues/533),
  [#534](https://github.com/ClaudioMascaro/meada/issues/534), [#535](https://github.com/ClaudioMascaro/meada/issues/535), [#536](https://github.com/ClaudioMascaro/meada/issues/536)): um `replace` do Go por outro
  módulo liga ao repositório do workspace que o caminho nomeia; uma fonte uv em
  `[tool.uv.sources]` liga ao único pacote que ela nomeia; especificadores PyPI são conferidos
  como a PEP 440 diz; um stub PyPI de mesmo nome no próprio repositório passa a `inferred`; e um
  `fetch` cuja URL uma função do repositório monta vira consumidor.
- **Packs** ([#596](https://github.com/ClaudioMascaro/meada/pull/596)): propriedades do Gradle e version catalogs preenchem
  coordenadas; macros de item do Rust dentro de `impl` e trait, e por `crate::`; globs
  `crate::a::*` dentro de `a` veem o que `use super::*` vê; `tsconfig.json` com `extends` herda
  `paths` e `baseUrl`.
- **Página de versões no console** ([#503](https://github.com/ClaudioMascaro/meada/issues/503)): um workspace nomeado lista suas
  versões, mostra entradas, manifesto e diff contra a atual, e aplica uma versão (rollback) pela
  confirmação do editor.
- **Deploy** ([#599](https://github.com/ClaudioMascaro/meada/pull/599)): o servidor de propostas roda no Compose
  (`compose.proposals.yaml`) e, opcional, no chart Helm (`proposals.enabled`); o cliente Postgres
  usa SCRAM com channel binding sobre TLS ([#483](https://github.com/ClaudioMascaro/meada/issues/483)); a probe de prontidão do Helm
  ganha `timeoutSeconds`; os scripts de fetch leem chaves entre aspas.
- **Primeira senha gerada** ([#579](https://github.com/ClaudioMascaro/meada/issues/579)): sem `admin_password_env` nem
  `admin_password_file`, o início que cria a conta `admin` gera a primeira senha, exige a troca e
  a imprime uma vez no stderr; não existe mais senha padrão publicada (ADR 0024 emendada).
- **Refresh mais curto** ([#391](https://github.com/ClaudioMascaro/meada/issues/391)): um refresh mantém os contratos e as chamadas de cada grupo
  de packs que resolvem juntos quando nenhum arquivo do grupo mudou; o export continua igual ao de
  um índice frio.
- **CLI em espanhol** ([#103](https://github.com/ClaudioMascaro/meada/issues/103)): `LANG` começando com `es` seleciona as mensagens
  em espanhol; a saída MCP continua em inglês.
- **Correções e regras** dos tiers b6 a c4 ([#598](https://github.com/ClaudioMascaro/meada/pull/598), [#600](https://github.com/ClaudioMascaro/meada/pull/600),
  [#604](https://github.com/ClaudioMascaro/meada/pull/604)): o console pergunta ao `meada-core` (WebAssembly) se nome, descrição e mensagem
  de versão valem; `[postgres] schema` com `pg_` é recusado na leitura do manifesto;
  `golden_diff` sai com mensagem em vez de pânico.

## Notas de atualização

- **Quem usa o crate `meada-core`**: `msg::pt()` deu lugar a `msg::lang()`, que devolve
  `msg::Lang` (`En`, `Pt`, `Es`), e `effective::Diagnostic::code` passou de `&'static str` para
  o enum `DiagnosticCode` (o JSON serializado é o mesmo). Quem fixava `meada-core = "=1.1.0"`
  sobe para `=1.2.0`.
- **Índice**: o resumo de manifestos gravado mudou (placeholders do Gradle), então um índice
  existente é reconstruído uma vez no primeiro uso.
- **Contas locais**: um `admin` novo não tem mais a senha padrão publicada; leia a primeira senha
  no stderr do início que criou a conta (`docker compose logs console | grep 'first password'`) ou
  defina `admin_password_env` ou `admin_password_file`. A regra `default_password` sai da política
  de senha. Uma conta que já existe não muda.
- **Compose e Helm**: os defaults apontam para `1.2.0`. Quem fixa `MEADA_VERSION` ou a versão
  do chart troca o valor ao atualizar.
- Nenhuma ferramenta MCP, linha de saída ou chave de configuração existente mudou de forma
  incompatível.

## Checklist de publicação

### Antes da tag

- [ ] PR `chore(release): 1.2.0` com CI verde, mergeado pelo mantenedor.

### Publicação pelo mantenedor

- [ ] Marcar a tag `v1.2.0` no commit do merge e enviá-la; isso dispara `release.yml`
  (rascunho do cargo-dist), `container.yml` e `publish-npm-staged.yml`.
- [ ] Publicar os crates: `meada-core` primeiro, depois `meada`.
- [ ] Aprovar com 2FA o pacote npm preparado (`npm stage list @meada/meada`, depois
  `npm stage approve <id>`).
- [ ] Revisar o rascunho e publicar a release do GitHub.

### Depois da publicação

- [ ] `npx @meada/meada --version` informa `1.2.0`, e `docker pull ghcr.io/claudiomascaro/meada:1.2.0`
  e `:1.2.0-cloud` funcionam.
