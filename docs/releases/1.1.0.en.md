# Meada 1.1.0

[Português (Brasil)](1.1.0.md) · **English** · [Español](1.1.0.es.md)

1.1.0 is a minor release under the [1.x stability promise](../site/en/stability.md): it only
adds, and no frozen item breaks. The tree declares **1.1.0** (workspace, the `meada-core` pin,
Dockerfile, compose defaults and Helm chart), and the `v1.1.0` tag follows the merge of the PR
that carries these notes. Publishing the crates, the staged npm package and the GitHub draft
release belongs to the maintainer. The detailed changes are in the [CHANGELOG](../../CHANGELOG.md).

## Changes

- **Local accounts** ([ADR 0024](../adr/0024-local-accounts-and-meada-signed-tokens.md), [#551](https://github.com/ClaudioMascaro/meada/issues/551)): local
  sign-in to the console with a password policy, account administration and groups, a break-glass
  account beside the identity provider, a verified GitHub login, Meada-signed agent tokens for the
  nodes, and named workspaces with the proposal server on those accounts. The `accounts` feature
  is part of `cloud`, so the 1.1.0 `-cloud` image carries it; the Compose recipe gains a
  one-command proof of concept and the Helm chart gains `modules.accounts`.
- **Export format and indexed commit** ([#512](https://github.com/ClaudioMascaro/meada/issues/512)): every `meada export` starts with
  `format` (1) and, when the index is fresh on a clean `HEAD`, carries `commit` and `dirty`.
  In server mode both come from the commit recorded beside the index, never from the mirror's
  live `HEAD`.
- **Postgres deadlines** ([#447](https://github.com/ClaudioMascaro/meada/issues/447)): every Postgres call has a client-side deadline,
  so a database that accepts the connection and stops answering ends in a 503 or an exit 1
  instead of hanging.
- **Durable generation writes** ([#518](https://github.com/ClaudioMascaro/meada/issues/518)): the `current` pointer, the version
  document, the pulled contexts and the exclusions file are synced before the rename, so a crash
  after the swap cannot leave `current` naming a document that never reached the disk.
- **Resolution in C#, Kotlin, Rust and Swift** ([#591](https://github.com/ClaudioMascaro/meada/pull/591)): in Rust, a call after `?`
  or `.await` is typed by the unwrapped value; in Kotlin, a bare call follows the language's
  order (an extension of the implicit receiver before a top-level function) and declarations
  nested in `expect` are `expect` too; in C#, `using static` imports only what the type
  declares and `internal` or `private` members of a public type count only in their own
  project; in Swift, an alias of an outside type reaches the repository's extensions and argument
  labels tell outside members apart.
- **Tier b1 and b2 fixes** ([#538](https://github.com/ClaudioMascaro/meada/pull/538), [#567](https://github.com/ClaudioMascaro/meada/pull/567), [#550](https://github.com/ClaudioMascaro/meada/pull/550)):
  hostile input in manifests, mirrors, imports, packs and fetch scripts; GitHub identities
  compared without case; Java and Kotlin in linear time for files with thousands of fields;
  `meada status` names files a pack drops for a limit; the console writes one
  `ui: directory: unreadable` line per request.
- **Docs**: the nine languages of 1.0 (TypeScript, JavaScript, Python, Go, Rust, Java, Kotlin, C#
  and Swift) described in the READMEs, the 1.0.0 notes and the user guides.

## Upgrade notes

- **`meada-core` crate users**: `Export` gains `format`, `commit` and `dirty` (the struct is
  `#[non_exhaustive]`), and `export::parse` refuses a document without `format`, naming the
  field. An export written by 1.0.0 no longer parses: re-export with 1.1.0 before reading it.
  Whoever pinned `meada-core = "=1.0.0"` moves to `=1.1.0`.
- **Index**: the schema version changed (new Rust facts), so an existing index is rebuilt once on
  first use.
- **Compose and Helm**: the defaults point at `1.1.0`. If you pin `MEADA_VERSION` or the chart
  version, change it when you upgrade.
- No existing MCP tool, output line or configuration key changed incompatibly.

## Publication checklist

### Before the tag

- [ ] `chore(release): 1.1.0` PR green in CI and merged by the maintainer.

### Maintainer publication

- [ ] Tag `v1.1.0` on the merge commit and push it; this triggers `release.yml` (the cargo-dist
  draft), `container.yml` and `publish-npm-staged.yml`.
- [ ] Publish the crates: `meada-core` first, then `meada`.
- [ ] Approve the staged npm package with 2FA (`npm stage list @meada/meada`, then
  `npm stage approve <id>`).
- [ ] Review the draft and publish the GitHub release.

### After publication

- [ ] `npx @meada/meada --version` reports `1.1.0`, and `docker pull ghcr.io/claudiomascaro/meada:1.1.0`
  and `:1.1.0-cloud` work.
