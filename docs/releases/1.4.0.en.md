# Meada 1.4.0

[Português (Brasil)](1.4.0.md) · **English** · [Español](1.4.0.es.md)

1.4.0 is a minor release under the [1.x stability promise](../site/en/stability.md): no frozen item
breaks. It is a release of fixes and a smaller values cache, minor because the export gains optional
fields and `context` and `search` gain marks at the end of a line. `meada status` stops reporting
orphans the code does not prove, Terraform evaluation names at `exact` only what Terraform creates,
and `meada mcp` takes large inputs without overflowing the stack or exhausting memory. The tree
declares **1.4.0** (workspace, the `meada-core` pin, Dockerfile, compose defaults and Helm chart),
and the `v1.4.0` tag goes on the `release/1.4` branch, cut from the merge of the PR that carries
these notes on main. Publishing the crates, the staged npm package and the GitHub draft release
belongs to the maintainer. The detailed changes are in the [CHANGELOG](../../CHANGELOG.md).

## Changes

- **`meada status` orphans** (ADR 0026; [#797](https://github.com/ClaudioMascaro/meada/issues/797),
  [#798](https://github.com/ClaudioMascaro/meada/issues/798), [#799](https://github.com/ClaudioMascaro/meada/issues/799),
  [#800](https://github.com/ClaudioMascaro/meada/issues/800)): an orphan line comes only from a side
  that proves its counterpart is missing.
  - A use Meada only infers from a key name (`queue`, `topic`, `bucket`, `table` or a typed alias)
    opens no orphan scope and is never an orphan line. It still links to a provisioner of its name
    and shows in `context` with `[inferred]`, and a `no provisioner` line ends with its side's
    level.
  - A structured identifier in the resource list of an IAM policy statement is a policy grant, no
    longer a use: it is never an orphan and no longer links to the provisioner it names, which hid
    a real `no use` line. `context` lists it with the role `policy grant`, and `meada export` in the
    `policy_grants` array.
  - Image orphans are asked for per registry and namespace (`ghcr.io/acme`, `docker.io/library`): a
    runner of a public image is no longer a `no builder` line. A group with no builders or no
    runners prints no line, and its sides carry `no builder in the workspace` or
    `no runner in the workspace` in `context` and `search`.
  - A document the reader of a kind recognizes as its own (a Prometheus, Loki or Grafana rule file,
    an Alertmanager configuration, a provider document) no longer feeds the key-name rule: a rule's
    `queue` label is no longer the use of a queue.
- **HTTP** ([#801](https://github.com/ClaudioMascaro/meada/issues/801)): a URL whose base Meada
  could not read (the return value of a call, a parameter no call binds, the base of a client no
  reader read), with a path appended to it, is an open item that names that limit, no longer a
  consumer linked to a guessed route. Its candidates are the routes that end with the known part,
  and `meada decide --list` and `search` show the limit.
- **Terraform and OpenTofu** ([#767](https://github.com/ClaudioMascaro/meada/issues/767),
  [#768](https://github.com/ClaudioMascaro/meada/issues/768), [#769](https://github.com/ClaudioMascaro/meada/issues/769),
  [#770](https://github.com/ClaudioMascaro/meada/issues/770), [#783](https://github.com/ClaudioMascaro/meada/issues/783),
  [#787](https://github.com/ClaudioMascaro/meada/issues/787)):
  - the elements of `list(string)`, `list(number)` and `list(bool)` are converted as Terraform
    converts them (`["010", "1.50"]` under `list(number)` names `10` and `1.5`);
  - a default its final type refuses, and a `for_each` over a tuple, give no exact name, as both
    tools refuse the configuration;
  - a variable declared in a `.tf` file and overridden in a `.tofu` file is exact only where
    Terraform and OpenTofu give it the same value; declared in both, the `.tf` block holds;
  - each root knows which of its variables hold a set, whatever root was evaluated before it;
  - a `terraform-aws-modules/s3-bucket/aws` call with `putin_khuylo = false`, or with a value Meada
    cannot resolve, provisions no bucket, and the Lambda module's call is read the same way.
- **AWS SDKs** ([#773](https://github.com/ClaudioMascaro/meada/issues/773),
  [#784](https://github.com/ClaudioMascaro/meada/issues/784)): a list of EventBridge entries held
  in a name and changed before `PutEvents` no longer names its first bus at `exact` in Java, Go and
  C#. In a file of more DynamoDB transactions than the evaluation budget covers, the call where the
  budget ends no longer gets an unresolved reader.
- **`meada mcp` and the index** ([#732](https://github.com/ClaudioMascaro/meada/issues/732),
  [#745](https://github.com/ClaudioMascaro/meada/issues/745), [#756](https://github.com/ClaudioMascaro/meada/issues/756),
  [#757](https://github.com/ClaudioMascaro/meada/issues/757), [#758](https://github.com/ClaudioMascaro/meada/issues/758),
  [#817](https://github.com/ClaudioMascaro/meada/issues/817), [#839](https://github.com/ClaudioMascaro/meada/issues/839)):
  - `trace` stops a branch 256 levels below its start and marks the line `(depth limit)`: a chain
    of about 2,000 calls overflowed the stack and aborted `meada mcp`;
  - a `trace` that reaches thousands of functions of one file takes time in proportion to them, not
    to their square, and `context` and the open items place their lines the same way;
  - `meada mcp` over stdio answers at most four calls at once, and the others wait their turn;
  - a call that waited behind another call's refresh in the same process no longer fails with
    `database is locked`, and a refresh reads the `[serve]` table when it starts;
  - a generic YAML or JSON file of more than 1,000 values is a data file: it keeps no config value,
    and `meada status` counts and names it apart;
  - the values cache (`values.db`) stores each entry deflated: on Meada's own repository it holds
    4.1 MB instead of 30.2 MB.

## Upgrade notes

- **Index**: the schema changed, so an existing index is rebuilt once on first use. `values.db`
  shrinks on the first refresh, which replaces its entries.
- **Data files**: a YAML or JSON file that only the config value reader takes loses its values
  once it holds more than 1,000, all its documents together, and a `value` search no longer finds
  them. Terraform and OpenTofu files, and the files a reader of a kind takes (a template, a
  Kubernetes object, a document, an alert rule, a workflow, a package manifest), keep every value.
- **Export**: the format stays 1. The `uses` rows gain the optional field `level`, and the
  optional array `policy_grants` is new.
- **Links that change**: where the earlier answer could name what the code does not touch, an
  `exact` link now has no exact name, stays unresolved or becomes an open item: the Terraform and
  EventBridge cases above, and the path appended to an unread base. Some links go: an IAM policy
  grant no longer links to its provisioner, a rule's label is no longer the use of a queue, a value
  under `examples`, `default`, `enum` or `const` of a JSON Schema gives no side, and an `s3-bucket`
  module call with `putin_khuylo = false` provisions no bucket. Some exact names change value, as
  `010` under `list(number)` becomes `10`. An `ambiguous-link` decision written for a call that
  became an open item goes stale, and `meada decide --prune` removes it; a `dynamic-url` decision
  that names one of the candidates still applies.
- **`meada status`**: the false orphan lines go, and some real ones 1.3.0 hid appear: a `no use`
  an IAM policy grant or a rule's label covered, and a `no provisioner` for the use of a bucket the
  `s3-bucket` module does not create with `putin_khuylo = false`. An automation that counts
  `no provisioner`, `no use`, `no builder` or `no runner` lines sees the numbers move both ways,
  and a `no provisioner` line ends with its side's level.
- **`meada mcp`**: a client that sends many calls without waiting for the replies has at most four
  in flight, and the others answer in their turn. A very deep `trace` ends with `(depth limit)`.
- **Users of the `meada-core` crate**: `export::Use` gains the field `level`, `export::Export`
  gains `policy_grants`, and `export::PolicyGrant` is new; all three are `#[non_exhaustive]`. To
  stay on 1.3, pin `meada-core = "~1.3"`.
- **Compose and Helm**: the defaults point at `1.4.0`. Whoever pins `MEADA_VERSION` or the chart
  version changes the value when upgrading. This release has no Postgres migration.

## Publication checklist

### Before the tag

- [ ] `chore(release): 1.4.0` PR green in CI and merged by the maintainer.

### Maintainer publication

- [ ] Tag `v1.4.0` on that merge commit, on a new `release/1.4` branch, and push both; this
  triggers `release.yml` (the cargo-dist draft and the job that stages the npm package).
- [ ] Publish the crates: `meada-core` first, then `meada`.
- [ ] Review the draft and publish the GitHub release; this triggers `container.yml` (images,
  Helm chart and `meada-ui-1.4.0.tar.gz`).
- [ ] Approve the staged npm package with 2FA (`npm stage list @meada/meada`, then
  `npm stage approve <id>`), only after the release is published: the npm installer downloads
  the binary from `releases/download/v1.4.0`, which answers 404 while the release is a draft.

### After publication

- [ ] `npx @meada/meada --version` reports `1.4.0`, and `docker pull ghcr.io/claudiomascaro/meada:1.4.0`
  and `:1.4.0-cloud` work.
