# Meada 1.5.0

[Português (Brasil)](1.5.0.md) · **English** · [Español](1.5.0.es.md)

1.5.0 is a minor release under the [1.x stability promise](../site/en/stability.md): no frozen item
breaks. It brings GitHub Actions into the graph: pipelines, actions, CI jobs and CI steps are
nodes, a new contract kind, `ci`, links each call of a reusable pipeline or an action across the
workspace's repositories, and a CI step's `run` script links to the packages it installs, the
programs it starts and the images it pushes. It is minor because `search` gains the kind `ci`, the
contract identifiers gain `ci::`, `context` and `search` gain line kinds and marks, and the export
gains optional fields. It also carries AWS SDK reading in Go and Java and fixes to Go, Java,
Terraform, Dockerfile, Backstage and decision reading. The tree declares **1.5.0** (workspace, the
`meada-core` pin, Dockerfile, compose defaults and Helm chart), and the `v1.5.0` tag goes on the
`release/1.5` branch, cut from the merge of the PR that carries these notes on main. Publishing the
crates, the staged npm package and the GitHub draft release belongs to the maintainer. The detailed
changes are in the [CHANGELOG](../../CHANGELOG.md).

## Changes

- **CI in the graph** (ADR 0028; [#823](https://github.com/ClaudioMascaro/meada/issues/823),
  [#824](https://github.com/ClaudioMascaro/meada/issues/824), [#825](https://github.com/ClaudioMascaro/meada/issues/825),
  [#826](https://github.com/ClaudioMascaro/meada/issues/826), [#827](https://github.com/ClaudioMascaro/meada/issues/827),
  [#829](https://github.com/ClaudioMascaro/meada/issues/829)):
  - a file under `.github/workflows/` that holds `jobs` is a pipeline, and an `action.yml` or
    `action.yaml` that holds `runs` is an action; each CI job and CI step is a node with its lines,
    its values and its references. `search` finds them with the new kind `ci`, and `context`
    explains them, a CI step also by a selector (`jobs.build.steps[id=login]`);
  - a CI job that calls a reusable pipeline of another repository of the workspace, and a CI step
    that calls an action of the workspace, link to it through the contract
    `ci::<repository identity>/<path>`. The link is `exact`, and its reason shows the Git ref as
    written and the provider's indexed commit (`@main (indexed 1a2b3c4)`), with `, ref mismatch`
    for a full commit id other than it. Every form of `uses` reads as GitHub resolves it, and a
    call inside its repository reads `own repository`;
  - `context` on a pipeline lists the CI jobs that call it with the keys of `with` and `secrets`
    they pass, and `trace` follows a chain of CI calls both ways, through reusable pipelines and
    composite actions;
  - `meada status` lists a reusable pipeline or an action nothing calls as an orphan of the CI
    contract, when the visible scope holds a provider and a consumer of it. A call to a path the
    workspace does not provide at the indexed commit is marked `(absent at the indexed commit)`,
    never an orphan or an open item. A CI step's `./<folder>` that Meada cannot place is an open
    item with no candidate and its cause;
  - the console's graph gains the view "CI links", its playground takes the kind `ci`, and
    `meada mcp --listen` answers the kind as stdio does.
- **What a CI step runs** (ADR 0028, ADR 0029; [#828](https://github.com/ClaudioMascaro/meada/issues/828),
  [#831](https://github.com/ClaudioMascaro/meada/issues/831), [#832](https://github.com/ClaudioMascaro/meada/issues/832),
  [#833](https://github.com/ClaudioMascaro/meada/issues/833), [#834](https://github.com/ClaudioMascaro/meada/issues/834),
  [#850](https://github.com/ClaudioMascaro/meada/issues/850)):
  - a `run` script is read through a command table, with no shell evaluated. `pip install` and its
    relatives make the CI step a consumer of a PyPI package of the workspace, and a console script
    of such a package starts its program, linked to the function the script names. Both links are
    `inferred`, their reason starting with `the name alone matched`: a fork or a copy of a public
    package may hold the name, so the level rises only when the package yardstick approves the
    rule;
  - `docker push` and `docker buildx build --push` are image builders, and an image builder read in
    a pipeline (`docker/build-push-action`, `docker/metadata-action`, ko) has the CI step as its
    site, no longer the repository. `context` on the CI step shows `builds <image>` and its
    runners;
  - a CI job that calls a reusable pipeline shows the `permissions` block that governs it, and the
    link's reason ends with `permissions mismatch` when a CI job of the called pipeline declares
    more than the caller's block holds. These are declared permissions, not effective ones;
  - in a pipeline or an action the key-name rule gives no use any more: `with: { bucket: x }` names
    an input of the action, not an S3 bucket. A structured identifier (an ARN, a queue URL,
    `s3://`, `gs://`) stays an `exact` use, sited on its CI step or CI job.
- **AWS SDKs** ([#772](https://github.com/ClaudioMascaro/meada/issues/772),
  [#774](https://github.com/ClaudioMascaro/meada/issues/774)):
  - Go: a DynamoDB transaction's list held in a name keeps its tables when it is also read by
    `len` or `cap`; a request, a list or an entry of a DynamoDB transaction or of EventBridge
    `PutEvents` keeps its table or bus when a wrapper takes it in a parameter and sends it, and
    when another function writes the same field through another name;
  - Java: a list of DynamoDB transaction entries that a wrapper takes in a parameter names its
    tables when no mention can change it before the request reads it.
<!-- 885 -->
- **Go and Java reading** ([#876](https://github.com/ClaudioMascaro/meada/issues/876),
  [#884](https://github.com/ClaudioMascaro/meada/issues/884), [#886](https://github.com/ClaudioMascaro/meada/issues/886),
  [#892](https://github.com/ClaudioMascaro/meada/issues/892), [#867](https://github.com/ClaudioMascaro/meada/issues/867)):
  - Go reads a file name's system or architecture suffix off the name cut at its first dot, as the
    Go tools do, and reads a package under `testdata` or a `_` directory only when a package Meada
    reads imports it;
  - a Go parameter list that groups ten names or more under one type keeps its first names;
  - a wrapper that calls itself with another value in the parameter a read needs no longer drops
    what the next turn sends;
  - Java reads a unicode escape of a line terminator (`\u000a`) as javac does, so a change written
    after one inside a line comment no longer leaves the old DynamoDB table named `exact`.
- **Terraform and OpenTofu** ([#763](https://github.com/ClaudioMascaro/meada/issues/763),
  [#765](https://github.com/ClaudioMascaro/meada/issues/765), [#792](https://github.com/ClaudioMascaro/meada/issues/792)):
  - evaluation sizes a variable once per expression and evaluates a name every instance of a
    `count` or `for_each` shares once, so large `count` values no longer leave names unresolved;
  - a template is evaluated as its parts, no longer parsed again each time: the templates in a
    `for` that 1.3.0 and 1.4.0 left unresolved are named exactly again;
  - a `bool` input of a registry module, or an `[[iac.module]]` mapping's `create`, given the
    string `"true"` or `"false"` reads as that bool, as Terraform converts it.
<!-- 749 -->
- **Dockerfile** ([#761](https://github.com/ClaudioMascaro/meada/issues/761),
  [#762](https://github.com/ClaudioMascaro/meada/issues/762)): a wildcard source counts every
  directory entry it examines, so 255 sources that match none of 4,000 files no longer take 47
  seconds; an instruction splits at ASCII blanks only, as Docker does.
- **Answers** ([#806](https://github.com/ClaudioMascaro/meada/issues/806),
  [#813](https://github.com/ClaudioMascaro/meada/issues/813), [#814](https://github.com/ClaudioMascaro/meada/issues/814)):
  - a `dynamic-url` decision applies only when its target is one of the candidates
    `meada decide` lists for the call; one outside them is stale with the cause `not-candidate`
    and the item stays open;
  - a Backstage backend module serves its routes under the `/api/<pluginId>` of the plugin it
    extends, where Backstage mounts them, no longer at the root;
  - `search` and `context` no longer mark a side `(no provisioner in the workspace)` when no IaC
    type can provision its kind (ADR 0026, amended).

## Upgrade notes

- **Index**: the schema changed, so an existing index is rebuilt once on first use. The rebuild
  reads every file under this version's rules, so every fix above applies at once. The CHANGELOG
  entries that say the schema version is the same and an index keeps its reading of a file until
  the file changes (#876, #884, #892) describe an index written by a build of main between
  releases, not one written by 1.4.0.
- **Export**: the format stays 1. A consumer of a CI contract gains the optional fields `ref`,
  `with` and `secrets`, left out when empty, and `absent` (`true`, left out otherwise); a consumer
  at a CI job gains `permissions`, the declared block that governs it. Pipelines, actions, CI jobs
  and CI steps are rows of `iac_nodes`, and the CI contract gives `providers`, `consumers` and
  `links` rows.
- **CI files** (#828): in a pipeline or an action, the `inferred` uses the key-name rule gave
  (`with: { bucket: x }`), their provisioning links and the orphan lines they fed are gone. A
  structured identifier stays an `exact` use, and the export writes the CI step or CI job that
  holds its key as the `site` of the use and the `side` of its provisioning link, in place of the
  repository.
- **Image builders** (#833): a builder read in a pipeline is sited on its CI step, not on the
  repository. The provider row, the link, `context` and `trace` name the CI step, and several CI
  steps of one repository that build an image are one builder with a link each. An automation
  that matched a builder by its repository identity matches the CI step's identity now.
- **Levels** (#850, ADR 0029): a CI step that installs a PyPI package of the workspace by name, or
  runs its console script, links to it at `inferred`, with a reason that starts with
  `the name alone matched`, never `exact`. The level rises in a later release once the package
  yardstick approves the rule that one provider of a name in the workspace is the package
  installed.
- **Links that change without a schema change of their own**: a `dynamic-url` decision that names
  no candidate of its call stops applying, goes stale with the cause `not-candidate`, and
  `meada decide --prune` removes it (#806); a Backstage module's routes move from the root to
  `/api/<pluginId>` (#813); Go files whose name holds a dot before the system suffix are read or
  left out as Go builds them, and a fixture program under `testdata` loses its providers and
  consumers (#876, #884); a Go wrapper with ten or more grouped parameters is followed to its
  callers (#892); a Java table named after an escaped line terminator in a comment is no longer
  `exact` (#867); Terraform names that a large `count`, a template in a `for` or a string bool
  left unresolved are named (#763, #765, #792).
- **`meada status`**: orphan lines of the CI contract appear where the visible scope holds a
  provider and a consumer of it, and the orphan lines the key-name rule fed from CI files go. A
  `(no provisioner in the workspace)` mark goes from the sides of a kind no IaC type provisions;
  the orphan lines are unchanged. An automation that counts orphan lines sees the numbers move
  both ways.
- **Users of the `meada-core` crate**: `export::Consumer` gains `git_ref` (serialized as `ref`),
  `with`, `secrets`, `absent` and `permissions`, and `export::Permissions`, `AllPermissions`,
  `Access`, `Secrets` and `Inherit` are new. To stay on 1.4, pin `meada-core = "~1.4"`.
- **Compose and Helm**: the defaults point at `1.5.0`. Whoever pins `MEADA_VERSION` or the chart
  version changes the value when upgrading. This release has no Postgres migration.

## Publication checklist

### Before the tag

- [ ] `chore(release): 1.5.0` PR green in CI and merged by the maintainer.
- [ ] `Release diff` job of the `chore(release): 1.5.0` PR green on its last head; in the PR's Evidence, each group of changes has its cause (a changelog entry or an issue), written by an agent that did not make the changes, and each vanished link and dropped level a verdict against the corpus code: no unexplained change and no regression (#852).
- [ ] The A9 yardstick ([#904](https://github.com/ClaudioMascaro/meada/issues/904)) approved under ADR 0029: the maintainer closed its ticket with every count inside its threshold, for each slice of the CI kind this release ships.

### Maintainer publication

- [ ] Tag `v1.5.0` on that merge commit, on a new `release/1.5` branch, and push both; this
  triggers `release.yml` (the cargo-dist draft and the job that stages the npm package).
- [ ] Publish the crates: `meada-core` first, then `meada`.
- [ ] Review the draft and publish the GitHub release; this triggers `container.yml` (images,
  Helm chart and `meada-ui-1.5.0.tar.gz`).
- [ ] Approve the staged npm package with 2FA (`npm stage list @meada/meada`, then
  `npm stage approve <id>`), only after the release is published: the npm installer downloads
  the binary from `releases/download/v1.5.0`, which answers 404 while the release is a draft.

### After publication

- [ ] `npx @meada/meada --version` reports `1.5.0`, and `docker pull ghcr.io/claudiomascaro/meada:1.5.0`
  and `:1.5.0-cloud` work.
