# Meada 1.2.0

[Português (Brasil)](1.2.0.md) · **English** · [Español](1.2.0.es.md)

1.2.0 is a minor release under the [1.x stability promise](../site/en/stability.md): no frozen item
breaks. The tree declares **1.2.0** (workspace, the `meada-core` pin,
Dockerfile, compose defaults and Helm chart), and the `v1.2.0` tag follows the merge of the PR
that carries these notes. Publishing the crates, the staged npm package and the GitHub draft
release belongs to the maintainer. The detailed changes are in the [CHANGELOG](../../CHANGELOG.md).

## Changes

- **Package reading** ([#532](https://github.com/ClaudioMascaro/meada/issues/532), [#533](https://github.com/ClaudioMascaro/meada/issues/533),
  [#534](https://github.com/ClaudioMascaro/meada/issues/534), [#535](https://github.com/ClaudioMascaro/meada/issues/535), [#536](https://github.com/ClaudioMascaro/meada/issues/536)): a Go `replace` by another
  module links to the workspace repository its path names; a uv source in `[tool.uv.sources]`
  links to the one package it names; PyPI specifiers are checked as PEP 440 says; a same-named
  PyPI stub in the consumer's own repository is `inferred`; and a `fetch` whose URL a function of
  the repository builds is a consumer.
- **Packs** ([#596](https://github.com/ClaudioMascaro/meada/pull/596)): Gradle properties and version catalogs fill coordinates;
  Rust item macros inside `impl` and trait blocks, and by `crate::`; a `crate::a::*` glob inside
  `a` sees what `use super::*` sees; a `tsconfig.json` with `extends` inherits `paths` and
  `baseUrl`.
- **Console versions page** ([#503](https://github.com/ClaudioMascaro/meada/issues/503)): a named workspace lists its versions,
  shows entries, manifest and the diff against the current one, and applies a version (a
  rollback) through the editor's confirmation.
- **Deploy** ([#599](https://github.com/ClaudioMascaro/meada/pull/599)): the proposal server runs in Compose
  (`compose.proposals.yaml`) and, opt-in, in the Helm chart (`proposals.enabled`); the Postgres
  client uses SCRAM channel binding over TLS ([#483](https://github.com/ClaudioMascaro/meada/issues/483)); the Helm readiness probe
  gains `timeoutSeconds`; the fetch scripts read quoted keys.
- **Generated first password** ([#579](https://github.com/ClaudioMascaro/meada/issues/579)): without `admin_password_env` or
  `admin_password_file`, the start that creates the `admin` account generates its first password,
  requires a change and prints it once on stderr; there is no published default password any more
  (ADR 0024 amended).
- **Shorter refresh** ([#391](https://github.com/ClaudioMascaro/meada/issues/391)): a refresh keeps the contracts and calls of each group of
  packs that resolve together when no file of the group changed; the export stays identical to a
  cold index's.
- **CLI in Spanish** ([#103](https://github.com/ClaudioMascaro/meada/issues/103)): a `LANG` starting with `es` selects Spanish
  messages; the MCP output stays English.
- **Backstage and HTTP contracts** (tier d1, [#678](https://github.com/ClaudioMascaro/meada/pull/678)): the router of a Backstage backend
  plugin is served under `/api/<pluginId>` ([#615](https://github.com/ClaudioMascaro/meada/issues/615)); a `fetch` to `/api/proxy/<endpoint>` links to
  the `target` of that endpoint in `proxy.endpoints` ([#616](https://github.com/ClaudioMascaro/meada/issues/616)); `config.getString('a.b')` resolves
  through the `app-config*.yaml` ([#617](https://github.com/ClaudioMascaro/meada/issues/617)); Go `env:"X"` fields ([#618](https://github.com/ClaudioMascaro/meada/issues/618)) and pydantic-settings
  fields ([#619](https://github.com/ClaudioMascaro/meada/issues/619)) count as environment reads; routes in test files are no providers unless
  `test_routes = true` ([#620](https://github.com/ClaudioMascaro/meada/issues/620)); `Get` and `Post` methods of a repository or Kubernetes client are
  no longer HTTP consumers ([#621](https://github.com/ClaudioMascaro/meada/issues/621)); a comment in a Go parameter list no longer shifts positions
  ([#613](https://github.com/ClaudioMascaro/meada/issues/613)); `express-promise-router` routes are providers ([#614](https://github.com/ClaudioMascaro/meada/issues/614)).
- **Fixes and rules** of tiers b6 to c5 ([#598](https://github.com/ClaudioMascaro/meada/pull/598), [#600](https://github.com/ClaudioMascaro/meada/pull/600),
  [#604](https://github.com/ClaudioMascaro/meada/pull/604), [#637](https://github.com/ClaudioMascaro/meada/pull/637)): the console asks `meada-core` (WebAssembly) whether a name, description and
  version message are valid; a `[postgres] schema` starting with `pg_` is refused at manifest
  read; `golden_diff` exits with a message instead of panicking; in tier c5, a Rust name two globs
  give is `ambiguous`, a Kotlin `private` constructor is called only from inside its class, a Swift
  parameter of an outside type neither takes nor refuses a trailing closure with certainty, a
  refresh resolves Swift as a cold index does (type parameters enter the index) and CommonJS
  `exports.y = ..` defines the symbol `exports.y`.

## Upgrade notes

- **`meada-core` crate users** (the Rust API is not frozen): a crate that declares
  `meada-core = "1.1"`, Cargo's default, gets 1.2.0 on `cargo update` and has three things to
  change. `msg::pt()` is gone: use `msg::lang() == msg::Lang::Pt` (`msg::lang()` returns
  `msg::Lang`: `En`, `Pt`, `Es`). `effective::Diagnostic::code` changes from `&'static str` to the
  `DiagnosticCode` enum: compare it with a `DiagnosticCode` instead of a string (the serialized
  JSON is the same). `named::message_problem("")` now returns `Some`: a version's message has a
  minimum of 1 character, so an empty message is refused. To stay on 1.1, pin
  `meada-core = "=1.1.0"`.
- **Index**: the stored manifest summary changed (Gradle placeholders), so an existing index is
  rebuilt once on first use.
- **Local accounts**: a new `admin` no longer has the published default password; read the first
  password on the stderr of the start that created the account (`docker compose logs console |
  grep 'first password'`) or set `admin_password_env` or `admin_password_file`. The
  `default_password` rule leaves the password policy. An existing account does not change: an
  `admin` created on 1.1.0 that still has 1.1.0's published default password keeps it. Change it
  now or reset it with `meada ui reset-admin --workspace <bootstrap manifest>`.
- **Mounted and test routes**: an Express app or router a function returns now takes the prefixes
  of its mounts (`app.use('/v1', makeRouter())` serves under `/v1/...`), and routes in test files
  are no longer providers; the links of some consumers change. `test_routes = true` in
  `meada.toml` keeps test routes as providers.
- **Compose and Helm**: the defaults point at `1.2.0`. If you pin `MEADA_VERSION` or the chart
  version, change it when you upgrade.
- No existing MCP tool, output line or configuration key changed incompatibly.

## Publication checklist

### Before the tag

- [ ] `chore(release): 1.2.0` PR green in CI and merged by the maintainer.

### Maintainer publication

- [ ] Tag `v1.2.0` on the merge commit and push it; this triggers `release.yml` (the cargo-dist
  draft and the job that stages the npm package).
- [ ] Publish the crates: `meada-core` first, then `meada`.
- [ ] Review the draft and publish the GitHub release; this triggers `container.yml` (images,
  Helm chart and `meada-ui-1.2.0.tar.gz`).
- [ ] Approve the staged npm package with 2FA (`npm stage list @meada/meada`, then
  `npm stage approve <id>`), only after the release is published: the npm installer downloads
  the binary from `releases/download/v1.2.0`, which answers 404 while the release is a draft.

### After publication

- [ ] `npx @meada/meada --version` reports `1.2.0`, and `docker pull ghcr.io/claudiomascaro/meada:1.2.0`
  and `:1.2.0-cloud` work.
