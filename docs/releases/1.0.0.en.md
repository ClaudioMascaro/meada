# Meada 1.0.0

[Português (Brasil)](1.0.0.md) · **English** · [Español](1.0.0.es.md)

These are the release notes for Release 1.0, [spec #32](https://github.com/ClaudioMascaro/meada/issues/32). The tree declares
**1.0.0**: the PR that finalizes these notes raises the workspace, the `meada-core` pin, the
Dockerfile, the compose defaults and the Helm chart, and the `v1.0.0` tag follows its merge on
main. Publication is still ahead and belongs to the maintainer under [#154](https://github.com/ClaudioMascaro/meada/issues/154):
`cargo publish` of the crates (core first), approval of the staged npm package with 2FA, and
publication of the GitHub draft release, which triggers the OCI image and Helm chart workflow.

## Prepared changes

The scope brings together HTTP routes, declared shared resources, OpenAPI and AsyncAPI
documents, channels and packages; levels on every link; cross-repository chains; decisions
with optional deciders; shape drift; TypeScript, JavaScript, Python, Go and Rust; and
deterministic communities and processes. Indexing still uses no LLM; a decider is opt-in
through `meada decide`.

R1 adds the [1.x stability promise](../site/en/stability.md), the
[normative English MCP grammar](../reference/output-grammar.md), surface goldens, usage
references in all three languages and a public-fixture CI benchmark. The promise starts
when 1.0 is published. Detailed changes, including the optional server and console features
already delivered, remain in the [CHANGELOG](../../CHANGELOG.md).
Earlier entries remain historical records; the `meada 0.1.0` build is the one of the first
acceptance receipt, below.

## Distribution and community

[ADR 0010](../adr/0010-distribution-and-community-practice.md),
[trunk #17](https://github.com/ClaudioMascaro/meada/pull/17) and [npm configuration #258](https://github.com/ClaudioMascaro/meada/pull/258) support the
channels: Cargo, binaries for six Linux/macOS/Windows targets (x86_64 and arm64), a shell
installer for Linux/macOS, npm, plus default/cloud OCI images and the console archive. See the
[distribution configuration](../../dist-workspace.toml),
[release workflow](../../.github/workflows/release.yml),
[container workflow](../../.github/workflows/container.yml) and
[image test](../../scripts/container-smoke).

**Configuration does not prove publication.** npm publication and real installation checks
remain the maintainer's work. `npx @meada/meada --version` and `npx @meada/meada mcp` against a public fixture
must be checked after publication. The prepared workflow leaves the GitHub release as a draft;
human publication triggers OCI distribution. To regenerate and check the entire workflow
with this policy, run `python3 scripts/release-workflow --write` and
`python3 scripts/release-workflow --check` at the root, with cargo-dist **0.32.0** on PATH.

The release workflow only stages the npm package: the
[staging workflow](../../.github/workflows/publish-npm-staged.yml) runs `npm stage publish`, and the
`NPM_TOKEN` secret cannot make a version public. The package is available on npm only after the
maintainer approves the staged version with 2FA (`npm stage list meada`, then
`npm stage approve <id>`). The GitHub release body that cargo-dist writes already shows
`npm install meada@<version>`, so the maintainer approves the stage before publishing the draft.
The first stage also creates a public `0.0.0-stage` placeholder, which is not a release.

The trunk's community practice includes [CONTRIBUTING](../../CONTRIBUTING.en.md),
[Code of Conduct](../../CODE_OF_CONDUCT.en.md) (Contributor Covenant 3.0) and
[SECURITY](../../SECURITY.en.md), each in pt-BR, English and Spanish; three
[issue forms](../../.github/ISSUE_TEMPLATE) and one
[PR template](../../.github/pull_request_template.md), each trilingual.
The moderation/reporting contacts still have fields for the maintainer to fill.
Required-check administration, private vulnerability reporting and contributor labels
need separate verification. File presence does not establish those settings.
Spanish CLI messages remain outside R1, in [issue #103](https://github.com/ClaudioMascaro/meada/issues/103).

## Public acceptance measurements

The sources for these measurements are two public receipts on #152. The [receipt from 2026-10-24](https://github.com/ClaudioMascaro/meada/issues/152#issuecomment-6379316350)
preserves two complete runs and records: AMD Ryzen 7 5825U, 16 logical CPUs, 7.16 GiB RAM,
Ubuntu 24.04.5 LTS, x86_64. The measured build was
`9b99c3a4091b6c1b2c590c43059763f25b6987ef`, `meada 0.1.0`; these are not measurements
of every later documentation head.

| Metric | Target | First complete run | Complete rerun |
| --- | --- | --- | --- |
| Cold configured-workspace index | <= 7 s | 12.680 s, not met | 2.711 s, met |
| Root index size | <= 37 MB | 21.057536 MB, met | 21.057536 MB, met |
| Single-file configured-workspace reindex | <= 1 s | 1.346 s, not met | 1.152 s, not met |
| Compact MCP `tools/list` result | <= 1,000 tokens | 622, met | 622, met |
| Largest default answer among 11 queries | <= 2,000 tokens | 1,996, met | 1,996, met |

MB means 10^6 bytes; the estimate is ceil(UTF-8 bytes / 4). Public fixtures supplement the
private workload in the receipt; it does not claim every feature naturally occurs in the
private root. Both sets of numbers are retained, without selecting only the better run.

The [receipt from 2026-10-30](https://github.com/ClaudioMascaro/meada/issues/152#issuecomment-6531862493) reruns the acceptance
on the same machine with the release build of main `1d648ad6` (after #391). The original setup
of 2026-10-24 was not kept, so the workspace was reconstructed and its absolute numbers are not
directly comparable with the earlier receipt; each run is the median of three samples, and the
table shows the quietest run and the range of the four.

| Metric | Target | Quietest run | Four runs |
| --- | --- | --- | --- |
| Cold configured-workspace index | <= 7 s | 5.586 s, met | 5.586 to 6.625 s, met in each |
| Root index size | <= 37 MB | 31.883266 MB, met | identical in each |
| Single-file configured-workspace reindex | <= 1 s | 0.931 s, met | 0.931 to 1.123 s, met in 2 of 4 |
| Compact MCP `tools/list` result | <= 1,000 tokens | 643, met | identical in each |
| Largest default answer among 11 queries | <= 2,000 tokens | 1,999, met | identical in each |

The rerun of 2026-10-30 meets four of the five targets: cold index (medians 5.586 to 6.625 s,
<= 7 s), root index size (31.883266 MB, <= 37 MB), `tools/list` (643 tokens, <= 1,000) and
largest default answer (1,999 tokens, <= 2,000). The single-file reindex (<= 1 s) met the target
in the two quieter runs (0.99 s and 0.931 s) and missed it in the two runs at a load average near
3 (1.068 s and 1.123 s). The maintainer
[waived the reindex target for 1.0.0](https://github.com/ClaudioMascaro/meada/issues/350#issuecomment-6532716065), recorded on [#350](https://github.com/ClaudioMascaro/meada/issues/350).

### Known limits

The single-file reindex sits near 1 s and exceeds it under load. #350 stays open for 1.x, with the
goal of 1 s with headroom under ordinary load; a speedup changes no output, so it ships as a patch
or minor release.

The [public CI benchmark](../../tests/it/benchmark.rs) retains JSON/Markdown and a job-summary
table. Its timings are informational and do not replace this private acceptance.
Existing tests continue to enforce deterministic token budgets.
