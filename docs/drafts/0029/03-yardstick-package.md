### Problema · Problem · Problema

Nothing measures how often a package link is right. Package links are in the gate of ADR 0029 (#N1) because a usage question is answered by reading them ("which repositories consume the packages a team publishes"). The dogfooding report of 1.3.0 holds no package item, which says only that nobody looked.

Meada reads no lockfile and queries no registry. A dependency links at `exact` to the one provider of that name in another repository of the workspace, on the assumption that the workspace holds the published package, whatever index serves the name. So a workspace that holds a fork or a copy of a public package under the same name links every consumer of the public package to the fork, at `exact`. Spec A9 builds on the same rule: an install by name in a CI step, and the program link that rests on it (#N5).

### Proposta · Proposal · Propuesta

The yardstick of the pair "package links", by the defaults of ADR 0029. This ticket records only what is particular to the pair.

1. **Origins.** The ecosystems in decreasing order of sides, down to the cut the gate list gives (#N1), plus every ecosystem the usage question exercises. An ecosystem below the cut stays unmeasured.
2. **Corpus.** Public code pinned by URL, commit and licence, chosen by a rule written in this ticket before any search and run by someone who does not implement readers. It asks for sets of repositories in which one publishes a package and another depends on it, with enough of them to reach the floor: 30 judged links per level, per ecosystem inside the cut, and across repositories.
3. **Distractor, from the start.** A public repository that is a fork or a copy of a public package and kept its name, added to a workspace whose consumers install the public one. A link from such a consumer to the fork is a wrong link. At `exact` it is a bug.
4. **Answer key.** The consumer's lockfile, read by the harness and never by indexing: it records where the installed package came from. Where a consumer has no lockfile, a model outside indexing judges, and the maintainer samples about 50 of its marks, the "correct" ones included.
5. **Thresholds.** The defaults: no wrong `exact` link, no silent absence, no `ambiguous` link whose candidates lack the right provider, at most 1 wrong `inferred` link in 10 (valid from 30 judged). Each cause of an open miss is an entry the maintainer approves with its expected count before the run.
6. **What it decides.** Its report approves, or not, the rule "one provider of a name in the workspace is the package a consumer installs". Until it does, an install by name alone in a CI step is `inferred` (#N5).

### Mais contexto · More context · Más contexto

- #537 asks whether Meada should read lockfiles and registry metadata. This yardstick does not change what indexing reads: the lockfile is its answer key only.
- The safety rule of the dogfood notes holds: third-party repositories are indexed, their code is never run and nothing is installed.

## Agent Brief

**Category:** enhancement
**Summary:** Measure the precision of package links per level and per ecosystem on a pinned public corpus that holds a fork with a kept name, against the consumers' lockfiles.

**Current behavior:**
A dependency links at `exact` to the one provider of its name in another repository of the workspace. No measurement says how often that provider is the package the consumer installs.

**Desired behavior:**
A repeatable run over a pinned corpus prints, as counts and not samples: links per level and per ecosystem; wrong links per level, each with the source the lockfile names; silent absences; open misses per approved cause; statements per ecosystem; what stays unmeasured under the floor; and the outcome of every consumer of the forked name.

**Key interfaces:**
- The `links` of `meada export` whose contract is a package contract: the unit that gets a verdict.
- The pinned inputs of `prove-meada`: the corpus list and a verdict file beside it.
- The consumer's lockfile, read by the harness.
- The gate list (#N1): the order and the cut of the ecosystems.

**Acceptance criteria:**
- [ ] The corpus rule is written in this ticket before the search, and the report names who ran it.
- [ ] The corpus holds at least one fork or copy that kept the name of a public package, and consumers whose lockfile names the public one.
- [ ] Every repository is pinned with URL, commit and licence.
- [ ] Each cause of an open miss has an entry the maintainer approved, with its expected count, before the run.
- [ ] The report gives the counts above and marks unmeasured whatever is under the floor of 30.
- [ ] A wrong `exact` link gets a failing test and a fix. Each other wrong link and each silent absence get a fix, or a ceiling the maintainer decides entry by entry.
- [ ] The report states whether the rule of item 6 is approved, and #N5 is told.
- [ ] The maintainer closes this ticket with every count inside its threshold. That is the approval the gate list records.

**Out of scope:**
- Reading lockfiles or registries in indexing (#537).
- A new ecosystem or a new contract kind.
- Ecosystems below the cut.
- Private repositories, or any data of a private workspace.

## Why a human

The order of ecosystems, the approved causes, the sample that calibrates the judge, each new ceiling and the closing are the maintainer's. The corpus search, the harness and the run can be done by agents who do not implement the readers.
