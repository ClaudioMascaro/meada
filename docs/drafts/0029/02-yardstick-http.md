Title: Yardstick: precision of HTTP links, with a distractor
Labels: enhancement, ready-for-human

> *This was generated by AI from the maintainer's decisions of 2026-11-13 (ADR 0029).*

### Problema · Problem · Problema

Nothing measures how often an HTTP link is right. HTTP links are in the gate of ADR 0029 (#N1) for two reasons: a usage question is answered by reading them ("which repositories consume the APIs a team publishes"), and the dogfooding report of 1.3.0 found an `inferred` link to the wrong route (#801, since fixed by rule in #845).

An HTTP link at `inferred` often rests on a route being the only one of its shape in the workspace. That holds less as a workspace grows, so a number taken on a small corpus says little about a large one. No test adds unrelated repositories to see which links move.

### Proposta · Proposal · Propuesta

The yardstick of the pair "HTTP links", by the defaults of ADR 0029. This ticket records only what is particular to the pair.

1. **Origins.** The origins of the pair in decreasing order of sides, down to the cut the gate list gives (#N1), plus every origin the usage question exercises. An origin below the cut stays unmeasured.
2. **Corpus.** Public code pinned by URL, commit and licence, beside the other pinned inputs of `prove-meada`. The rule that chooses it is written in this ticket before any search, and run by someone who does not implement readers. It asks for sets of repositories of one owner in which one serves routes and another calls them, with enough of them to reach the floor: 30 judged links per level, per origin inside the cut, and across repositories.
3. **Answer key.** No record of execution exists for public code here, so a model outside indexing judges each link against the source: the call site, the route and its handler. The maintainer samples about 50 of its marks, the "correct" ones included, before the report counts.
4. **Verifier.** It lists the calls and the routes from the source before it opens the export, so that it also finds what Meada did not state.
5. **Thresholds.** The defaults: no wrong `exact` link, no silent absence, no `ambiguous` link whose candidates lack the right provider, at most 1 wrong `inferred` link in 10 (valid from 30 judged). Each cause of an open miss (a dynamic URL, a base Meada cannot evaluate, a ceiling) is an entry the maintainer approves with its expected count before the run.
6. **Distractor.** The run is repeated with unrelated public repositories added, chosen by the same corpus rule. The report counts how many routes of the distractor collide with routes the corpus calls. With no collision, the distractor is unmeasured, not passed. Each link then has one of three outcomes: it does not change; it becomes `ambiguous` (expected, and counted); it stays `inferred` and changes its target (a wrong link). An `exact` link that changes is a bug. The count of links that became `ambiguous` enters the known ceilings as a measured value.

## Agent Brief

**Category:** enhancement
**Summary:** Measure the precision of HTTP links per level and per origin on a pinned public corpus, without and with a distractor, against verdicts the builder of the readers did not write.

**Current behavior:**
HTTP links are checked on fixtures written for the rules. No number says how many are right on code nobody wrote for the tests, or how many change when unrelated repositories join the workspace.

**Desired behavior:**
A repeatable run over a pinned corpus prints, as counts and not samples: links per level and per origin; wrong links per level; silent absences; open misses per approved cause; statements per origin; what stays unmeasured under the floor; and the three outcomes of the distractor with its collision count.

**Key interfaces:**
- The `links` of `meada export` whose contract is an HTTP contract: the unit that gets a verdict.
- The pinned inputs of `prove-meada`: the corpus list and a verdict file beside it.
- The gate list (#N1): the order and the cut of the origins.

**Acceptance criteria:**
- [ ] The corpus rule is written in this ticket before the search, and the report names who ran it.
- [ ] The corpus and the distractor are pinned with URL, commit and licence.
- [ ] Each cause of an open miss has an entry the maintainer approved, with its expected count, before the run.
- [ ] The judge's marks are sampled by the maintainer (about 50, the "correct" ones included) before the report counts.
- [ ] The report gives the counts above, per level and per origin, and marks unmeasured whatever is under the floor of 30.
- [ ] A wrong `exact` link gets a failing test and a fix. A wrong `inferred` or `ambiguous` link and each silent absence get a fix, or a ceiling the maintainer decides entry by entry.
- [ ] The distractor's count of links that became `ambiguous` is in the known ceilings.
- [ ] The maintainer closes this ticket with every count inside its threshold. That is the approval the gate list records.

**Out of scope:**
- A new reader, a new language or a new contract kind.
- Origins below the cut.
- Private repositories, or any data of a private workspace.

## Why a human

The order of origins, the approved causes, the sample that calibrates the judge, each new ceiling and the closing are the maintainer's. The corpus search, the harness and the run can be done by agents who do not implement the readers.
