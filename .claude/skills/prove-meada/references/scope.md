# Scope table

`SKILL.md`'s Scope step reaches this table: `scripts/prove-ci --rows <paths>` prints the rows
a change reaches, and the flows CI runs for it.

CI runs this table: `scripts/prove-ci` runs each driver a row names when a path the row names
changed (`FLOWS` there; a change to the verifier or to shared core runs them all), with
`meada-head`, the merge-base `meada-base` and, in a console run, `meada-head-ui` (`BIN`, `BASE`,
`UI_BIN` below). Each driver is a step of `receipt.json`, its evidence under `flows/<name>` in the
`prove-meada-<PR>-<head>` artifact. Its self-test fails when a driver named here is not in
`FLOWS`. A row with no driver of its own is the corpus capture: `cli-mcp` runs `prove.py run` with
`BIN` against `BASE` (CLI, MCP stdio and HTTP) over the corpus entries `scripts/check --ci`
selects, and a console run starts `console.py` with `UI_BIN` over the same entries, then the
pages; `tests/golden/` runs `goldens` (`prove.py rebless` against the base commit), and deploy
paths run `prove.py deploy`, `scripts/compose-check` and `scripts/helm-check`. A driver's exit 1
fails its step, except `prove.py values` and `iac`, whose exit 1 is a difference from the base:
recorded as evidence, as `cli-mcp`'s is (an answer their key rejects exits 3 and fails it). The
CLI flows run after `cli-mcp`, the console's after its API checks and before its pages. Every step
but the cleanups runs under `timeout` with what is left of a 45-minute capture, a flow for at most
20 minutes, so the receipt is written inside the job's 60: a step that times out, or that would
start with under a minute left, is BLOCKED. A row says where CI differs, and names what CI does not
run and what the reviewer does instead.

## An input for a new flow

CI captures only inputs the tree holds: the `corpus.tsv` and `infra.tsv` entries and the
workspaces each driver generates. When the change reaches a construct no input has (#740: no
captured input declared a Terraform variable a set, so the judge could only say UNPROVEN), add
one in the same PR:

1. Write a probe directory `scripts/<name>/` from the spec, never from the product's answer: the
   smallest source that reaches the construct, and a `README.md` naming the issue and the key.
2. Add it to `infra.tsv` (`<name>`, its flows, `probe:<name>`, `-`, the license; a public
   repository takes its URL and pinned SHA instead), and to the `--repos` of its flow in
   `FLOWS` (`scripts/prove-ci`). An entry the flow's oracle reads joins its comparison.
3. Where the oracle cannot read the construct, the probe carries the key in the reference tool's
   own answers, and the flow compares with it; failing that, the judge compares the evidence with
   the README's key by hand.

Worked input: `a7-tf-set` (#740), a root per row of the maintainer's table with the issue's
resource, and `terraform-names.tsv` with Terraform v1.17.1's names (`rejected` where Terraform
refuses the configuration). `tf_names.py` reads no override file, so `prove.py iac` leaves these
roots out of its oracle and asks `search` kind `iac` for the key's type instead: an exact name must
be Terraform's, a rejected root has none, and a root without an exact name is reported, not
failed (certain or absent). The judge reads the `terraform key` line of `flows/iac/iac.md`, the
raw answer in `flows/iac/head/a7-tf-set/iac.json` and the probe's README, and decides whether an
absent row meets #740's acceptance.
