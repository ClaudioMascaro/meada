# Azure SDK use sides (#670)

Run the permanent A7 flow, using the built candidate rather than the installed MCP binary:

```bash
python3 "$S/azure-sdk.py" --head-bin "$RUN/bin/meada-head" --run "$RUN/azure-sdk" --http
```

`--seed-only` writes all neutral repositories, source hashes and explicit whole-role oracles
before product answers. The answer keys are #670/#642, ADR0026's adopted operation matrix
and the official SDK API inventory, never product output or a newly blessed golden. The
script's checks are scaffolding from the implementing agent; a fresh checker owns the verdict.

The six source languages cover Service Bus send, queue/subscription receive, Event Hubs
send/receive, Blob container write/read and Key Vault secret read. Adjacent documented
operations, explicit hub/constructor variants, Python sync/aio/context managers, structured
selectors, wrong-service identifiers and unread hub names have complete side inventories.
Origin controls retain separate sibling factory names and exercise hidden constructors,
typed-only clients, reassignment, opaque alternatives and actual inferred/ambiguous hops.

The workload case uses three containers running the same image, with crossed topic/subscription
names, literal companions, unread secret companions in the selected container and slash queue names. Typed Function
app settings distinguish topic, subscription and queue targets and retain filtered delivery.
Private identities are read from SQLite only to verify normalized selector components and
the absence of both real constructor credentials and an invalid name-argument canary. Public
exports and all MCP answers must exclude those credentials and private receiver fields.

CLI exports use whole provider/consumer multisets; the minimum also checks complete exact
link counts. MCP stdio and HTTP compare complete tool lists and answers. The environment
HTTP server is then queried after source removal: contract and execution scope must remain
available. Missing locations/snippets and the existing stale-mirror notice are expected there;
do not claim byte parity with source-present presentation. The Engine stored-export regression
checks complete source-deleted JSON parity, excluding only commit/dirty provenance.
Edit/restore probes rename queue selectors and compare restored complete exports.

Plain and structured workload values also drive Event Hubs, Blob and Key Vault normalization.
The public Engine suite additionally replaces each service selector with environment reads in
all six source languages, retaining same-file literal positive controls.

Before acceptance, a fresh checker also drives these cases with independently chosen names:

- Two calls returning subscription receivers, with differing topic and subscription arguments;
  include structured/destructured actuals and environment/literal mixtures. No companion may
  leak from another exact frame or same-spelled local.
- A valid first structured factory argument followed by a same-valued object whose companion
  is changed through assignment, an alias and a supported mapping mutation. Memo normalization
  and final name folding must both reject stale names; a handle captured before a later write
  and an unrelated sibling object must retain their names. Preserve actual RED/green answers.
- Unknown or unread companions in the same container, separate workloads, separate IaC roots,
  unrelated images and ambiguous builders. Reject cross-container and image-wide tuple joins.
- Same-short-name topic/subscription, filtered and unfiltered subscription delivery, literal
  and typed selectors, slash queues and malformed/wrong-service ARM/URL values. Check complete
  provision/delivery sets and their levels/reasons, including workload provenance.
- Repeated Blob and secret reads in one function remain distinct operation call sites; an
  unknown object, group, partition or secret version must not erase a known resource name.
- Existing C# sends, schedules, accepted typed origins and topic processors match the frozen
  base. Existing Azure provisioners/config, GCP/AWS SDKs, native brokers and workload
  environments use their established flows and exact-base controls. Shared schema changes
  rebuild older source indexes through the existing schema-golden version mechanism.

Record the source hashes, binary SHA, raw exports, status, MCP answers, private canary check,
whole comparisons and unchecked scope in the receipt. A minimum script pass does not establish
all supplementary scope. Same-agent checks are not independent proof; the parent integration
owns fresh review/proof, the feature Clippy matrix and exact-head CI.

A queue receiver and subscription receiver with the same handler and `env:BUS` must both
survive internal declaration deduplication before workload resolution. The same-handler flow
checks both resulting contracts through CLI and MCP, without exposing their private identity.
